# Interface languages

English is the main language; Turkish is the second one.

## How the language is chosen

1. If the user picked a language (Options menu, or Portal view → Start → User interface language), it is stored
   in the `plc_lang` cookie and always wins.
2. Otherwise the browser decides: the first entry of `Accept-Language` (server) / `navigator.languages` (client)
   whose primary subtag is `en` or `tr`. Anything else → English.

The server renders the page in that language (`app/page.tsx`, `app/layout.tsx`), so there is no flash of the
wrong language.

## Code pattern

- `src/i18n/core.ts` has no framework dependencies. Use it from React, the PLC Web Worker and the server API.
- **UI components:** use one dictionary per area in `src/i18n/dict/<area>.ts`, built with
  `defineDict(en, tr)`. The compiler rejects a Turkish table that misses a key. In a component:
  `const t=useT(areaDict); t('key',{param})`. `useLang()` gives `{lang,setLang}`. Reference implementation:
  `src/ui/PortalView.tsx` with `src/i18n/dict/portal.ts`.
- **Non-React code** (compiler, runtime, evaluator, worker, API route): take a `lang:Lang` parameter that
  defaults to `'en'`, and use `translator(dict,lang)`.
- **Data that carries both languages** (exercise text): `{en:'…',tr:'…'}` values, read with `pick(text,lang)`.
- **Placeholders:** `{name}`, filled by `format` / `t(key,params)`.
- **API:** the client sends `lang` (GET query `lang=`, POST body `lang`). The server validates it with
  `langOf()` and answers in that language.
- **Test results:** `name` is the stable English key (used by tests and logic); `title` is the localized display
  text. The UI shows `title`.
- **Stable identifiers are never translated:** concept ids (`Seal-in`, `Timers`, …), tag names, addresses,
  test names used as keys, enum values, CSS classes, `data-*` attributes.

## Glossary (EN → TR)

Keep these as they are in both languages: PLC/TIA identifiers and mnemonics (OB1, OB100, Main, Startup, LAD,
NO, NC, TON, TOF, TP, CTU, CTD, CTUD, MOVE, CMP, P_TRIG, N_TRIG, RUN, STOP, EN/ENO, %I/%Q/%M addresses,
tag names, CPU names, PLC_1, HMI_1, "Network").

Turkish style: use the informal "sen" form, as the existing training text does ("START’a bas"). Use the
apostrophe ’ for suffixes on codes and names: OB1’i, CPU’yu, START’a.
